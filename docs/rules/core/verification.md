# 验证规则

工具原理见 wiki [对照 playground 与对比脚本](../../wiki/engineering/01-playground-and-compare.md)。

## 对照用例

- 每个迁移的组件必须在 `playground/src/demos/<X>Demo.vue` 里有对照用例，并在 `App.vue` 的 `demos` 里注册。
- 用例必须覆盖：所有变体、所有状态色、禁用、尺寸，以及组件特有的形态（图标、前后缀、加载、错误态等）。
- EP 的外观属性（尺寸、类型、效果、颜色、宽度、对齐等）的非默认取值各至少一个用例，确认主题下仍然生效；Arco 没有对应项的用不成对的展示用例，看截图确认。
- 两侧成对元素必须用相同的 `data-pair` 包起来，EP 和 Arco 的用法要语义对等（同样的文字、同样的状态）。
- 新组件的测量目标选择器要加进 `scripts/screenshot.mjs` 的 `TARGET`；需要测内部部件、位置或宽度时用 `data-target` / `data-pos` / `data-width`（见 wiki 对照工具篇）。
- 弹出层、需要滚动才出现的组件不在自动测量范围内，必须用脚本打开后核对几何与颜色，并在 wiki 组件篇里写明核对方式。
- `data-skip` 只能用于两边行为本来就不同的状态（例如 EP 的 loading 按钮带 `disabled`、无法获得焦点），必须在交付说明里写出原因。

## 必须通过的回归

| 改动范围 | 必须执行 |
| --- | --- |
| 组件覆盖（亮色） | `pnpm shot`、`pnpm shot:ondemand` |
| 涉及暗色 | 上述两项，再加 `pnpm shot --dark`、`pnpm shot --mode ondemand --dark` |
| 全局 token、构建、插件、对比脚本 | 四种组合全部执行，覆盖所有已迁移组件 |
| Arco 兼容变量（`src/generated/`） | 四种组合，加上 wiki 里记录的变量隔离比对 |

- 四种组合可以用 `pnpm shot:all` 一次并行跑完（含构建和 `pnpm verify:vars`），它会先起好并预热两个 dev server，输出每组的结果汇总。
- 每种组合的报告必须是 0 处差异，才算通过。
- 报告归零后必须查看 `.compare*/` 下的截图，确认报告测不到的部分（图标、伪元素、遮罩、文字格式）也一致。
- 只有亮色全量模式归零，不能宣称完成。

## 禁止

- 禁止为了让报告归零而放宽 `same()` 的容差、删除测量字段或加 `data-skip`。对比口径只能在“修正误报”时调整，例如两边语义相同但表达方式不同（inset box-shadow 和 border、超过半高的圆角）。调整时必须在交付说明里写明误报的原因。
- 禁止复用别人正在运行的 dev server 的结果来宣称新代码通过：脚本会复用已经在端口上的 server，改了 `vite.config.ts` 或插件后，必须确认该 server 已经重启或由脚本自己启动。
- 对比脚本失败时，必须保留原始错误输出，不能只重跑一次通过就当作没发生。

完成标准：交付说明里列出执行过的每种组合及差异数，以及看过的截图。
